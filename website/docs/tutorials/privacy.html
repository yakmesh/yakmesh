Privacy Guide

10 min read

What's shared, what's private, and how to control it

Understand exactly what information YAKMESH reveals and what stays completely private. Learn how to maximize your anonymity on the mesh.

1 The Big Picture

YAKMESH is designed with privacy as a core principle. Unlike traditional services that know everything about you, YAKMESH only shares what's absolutely necessary for the network to function.

Think of it like this: In a traditional web service, you're walking through a building with security cameras everywhere—every move is recorded. In YAKMESH, you're in a dark maze where others can only see the flashlight beam you're pointing, not who's holding it.

The key insight: YAKMESH separates identity from content. Your node has a public identity (for the network), but that identity doesn't have to be linked to you personally.

2 What YAKMESH Shares

For the network to work, some information must be visible. Here's what other nodes can see about you:

Information Who Sees It Why It's Needed
🔑 Node ID (public key) All connected peers To identify and authenticate your node
📋 Content hashes you host Nodes you share with So others know what content you have
🌐 Mesh connection status Direct peers only To maintain network connections
⏱️ Time capability level Peers during trust checks For KARMA trust scoring

Important: Your Node ID is like a username—it identifies your node but doesn't reveal who you are in real life. You can generate a new identity anytime.

3 What Stays Private

These things are never shared with the network:

  • 🛡️
    Your IP address (behind the mesh)
    When routing through the mesh, intermediate nodes only see the previous and next hop—not your real IP. Direct connections still expose IP to that specific peer.
  • 🔐
    Your content (encrypted)
    Content is encrypted at rest in STUPA storage. Even if someone accesses your disk, they can't read your files without the keys.
  • 👤
    Your real identity (anonymous by default)
    YAKMESH never asks for your name, email, or any personal information. Your node is just a cryptographic key pair.
  • 📍
    Your location (unless you enable geo-proof)
    Geographic proof is opt-in. Without it, nobody knows where you're running from.
  • 🔑
    Your private keys (never leave your device)
    Only your public key is shared. Private keys stay on your machine and are never transmitted.

4 What Your Peers Can See About You

Different peers have different visibility levels:

🔌 Direct Peers (you connect to them directly)

  • • Your IP address (unavoidable for direct TCP/UDP connections)
  • • Your node ID and public key
  • • When you're online/offline
  • • Content you're requesting or serving to them

🔀 Relay Peers (routing your traffic)

  • • Previous hop and next hop only
  • • Encrypted packet size and timing
  • • Cannot see: origin, destination, or content

🌍 The Broader Network

  • • Your node ID exists (if you participate in gossip)
  • • Content hashes you've announced
  • • Cannot see: your IP, location, or what you're browsing

5 Privacy Settings in Config

You can customize your privacy level in yakmesh.config.js: 

export default {
  // Privacy settings
  privacy: {
    // Don't announce content to the network
    // (you can still serve content to direct peers)
    announceContent: false,
    
    // Use onion routing for all outbound requests
    forceOnionRouting: true,
    
    // Minimum number of relay hops
    minRelayHops: 3,
    
    // Don't participate in mesh gossip
    // (reduces visibility but limits features)
    disableGossip: false,
    
    // Reject direct connections (relay only)
    relayOnly: false,
  },
  
  // Geo-proof is opt-in
  geoProof: {
    enabled: false,  // Don't reveal location
  },
}

Trade-off: More privacy often means reduced functionality. For example, disableGossip hides you from the network but means you won't discover peers automatically.

6 Anonymous Mode

For maximum privacy, enable full anonymous mode: 

# Start node in anonymous mode
npx yakmesh start --anonymous

# Or set in config
npx yakmesh config set privacy.anonymousMode true

Anonymous mode enables these protections automatically:

  • ✓ Forces all traffic through onion routing (3+ hops)
  • ✓ Disables content announcements
  • ✓ Generates ephemeral session keys (rotated frequently)
  • ✓ Adds random delays to timing analysis resistance
  • ✓ Pads packets to uniform sizes
Trade-off warning: Anonymous mode is slower (more hops, delays) and uses more bandwidth (padding). It also limits your ability to host content for others. Use it when privacy is more important than performance.

7 What About Metadata?

Metadata (data about data) can be just as revealing as content. Here's how YAKMESH handles it:

Metadata Type Protection Level
Request timing Random delays in anonymous mode
Packet sizes Padded to uniform sizes in anonymous mode
Connection patterns Visible to direct peers; hidden behind relays
Online times Direct peers know when you connect
Content request frequency Encrypted and routed through mesh

Best practice: Use multiple direct peers so no single peer sees all your activity patterns. The mesh naturally distributes your traffic.

📌 Key Takeaways

  • ✓ Shared: Node ID, content hashes, connection status
  • ✓ Private: IP (behind mesh), content (encrypted), real identity, location
  • ✓ Privacy settings in config let you control visibility
  • ✓ Anonymous mode provides maximum protection with performance trade-offs
  • ✓ Direct peers see more than relay peers
  • ✓ You can regenerate your node identity anytime for a fresh start
