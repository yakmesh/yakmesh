Security for Non-Techies

12 min read

Keep your node safe without a computer science degree

Practical security advice for running a YAKMESH node. We'll explain firewalls, quantum-resistant crypto, and warning signs—all in plain English.

1 Firewall Basics: What Ports to Open

What's a firewall? Think of it as a bouncer at a club. It decides which network traffic gets in and which gets blocked. Ports are like different doors— each service uses a specific numbered door.

YAKMESH needs a few ports open to work. Here's what they do:

Port Service Required? Notes
9525 YAKMESH P2P Yes Main mesh communication
9526 Dashboard UI Local only Keep this local—don't expose to internet
9527 API Optional Only if you need remote API access
443 HTTPS Gateway Optional If serving websites via NAMCHE

Quick Firewall Setup

On Windows (PowerShell as Admin):

# Allow YAKMESH P2P port
New-NetFirewallRule -DisplayName "YAKMESH P2P" -Direction Inbound -Port 9525 -Protocol TCP -Action Allow

On Linux (UFW):

# Allow YAKMESH P2P port
sudo ufw allow 9525/tcp

# Check status
sudo ufw status

On macOS:

# macOS firewall is managed through System Preferences
# Go to: System Preferences > Security & Privacy > Firewall > Firewall Options
# Add Node.js to allowed apps

2 What's Safe to Expose, What's Not

Not everything should be accessible from the internet. Here's a simple guide:

Safe to expose to the internet:
  • • Port 9525 (P2P mesh) — This is designed for public access
  • • Port 443 (HTTPS gateway) — If you're hosting a website
  • • Content you explicitly share — YAKMESH won't leak other files
Keep local only (don't expose):
  • • Port 9526 (Dashboard) — Anyone could control your node
  • • Port 9527 (API) — Unless you've set up API authentication
  • • Your data/ folder — Contains your private keys
Think of it like your house: The front door (P2P port) is made for visitors. But you wouldn't give strangers access to your bedroom (dashboard) or your safe (private keys).

Binding to Localhost

By default, your dashboard only listens on localhost (127.0.0.1), meaning only your computer can access it. Don't change this unless you know what you're doing. 

// In yakmesh.config.js - SAFE defaults
export default {
  dashboard: {
    host: '127.0.0.1',  // Only local access - KEEP THIS
    port: 9526,
  },
  p2p: {
    host: '0.0.0.0',    // All interfaces - OK for P2P
    port: 9525,
  },
}

3 Quantum-Resistant Crypto (Simple Terms)

You've probably heard us mention "quantum-resistant" or "post-quantum" security. Here's what that actually means for you:

The problem: Future quantum computers could break the encryption that protects most of the internet today. It's like having a super-lockpick that can open any traditional lock.

The solution: YAKMESH uses new types of encryption that quantum computers can't break. These are based on different math problems.

What YAKMESH Uses

  • 🔐
    ML-DSA-65 (for signatures)
    Proves messages really came from you. Based on mathematical lattices—imagine a 3D grid that's hard to navigate backward.
  • 🔒
    Kyber (for key exchange)
    Lets two nodes agree on a secret key securely. Also lattice-based.
  • 🛡️
    AES-256 (for encryption)
    The actual encryption of your data. Already quantum-resistant with 256-bit keys.

What This Means for You

Good news: You don't need to do anything special. YAKMESH handles all of this automatically. Your data is protected against both today's computers and tomorrow's quantum computers.

You can verify your node is using quantum-resistant crypto: 

npx yakmesh security check

# Should show:
# ✓ ML-DSA-65 signatures: Active
# ✓ Kyber key exchange: Active
# ✓ AES-256 encryption: Active

4 Keeping Your Node Updated

Updates fix security holes. An outdated node is a vulnerable node. Here's how to stay current:

Check for Updates

# See your current version
npx yakmesh --version

# Check if updates are available
npm outdated yakmesh

Install Updates

# Update to latest stable version
npm update yakmesh

# Or for major updates
npm install yakmesh@latest

Enable Auto-Update Notifications

// In yakmesh.config.js
export default {
  updates: {
    checkOnStartup: true,     // Check for updates when node starts
    notifyInDashboard: true,  // Show update banner in dashboard
  },
}
Before major updates: Always backup your data/ folder first. Major version updates might include changes that need migration.

Update frequency: Security patches are released as needed (check announcements). Feature updates come monthly. We recommend updating within a week of any security release.

5 Signs of Trouble (What to Watch For)

Your node will usually tell you if something's wrong. Here are warning signs to watch for:

🚨 Sudden spike in bandwidth or CPU

What it might mean: Someone might be abusing your node, or you're under a denial-of-service attack.
What to do: Check the dashboard for unusual peer activity. Consider temporarily restricting connections.

🚨 Many failed authentication attempts

What it might mean: Someone is trying to guess credentials or exploit your node.
What to do: Check logs for the source. Block repeated offenders. Ensure your API has authentication enabled.

🚨 Unexpected peers connecting

What it might mean: Could be normal mesh discovery, or could be someone trying to eclipse your node.
What to do: Check peer diversity. If all new peers are from the same source, that's suspicious.

🚨 KARMA score dropping unexpectedly

What it might mean: Your node might be serving bad data or having connectivity issues you're not aware of.
What to do: Run npx yakmesh diagnose to check for problems.

🚨 Warnings about time sync

What it might mean: Your system clock is drifting, which affects security and trust scoring.
What to do: Enable NTP time sync on your computer. Check your internet connection.

Quick Health Check

# Run a full diagnostic
npx yakmesh diagnose

# Check security status
npx yakmesh security audit

# View recent warnings
npx yakmesh logs --level=warn --last=50

6 If Something Goes Wrong

If you suspect your node has been compromised:

  1. 1
    Stop the node immediately
    npx yakmesh stop or just close the terminal
  2. 2
    Disconnect from the network
    If it's serious, physically disconnect your computer from the internet
  3. 3
    Check what happened
    Review logs in data/logs/
  4. 4
    Generate new identity if compromised
    npx yakmesh identity regenerate
  5. 5
    Report the issue
    Contact us at security@peerquanta.com
Prevention is better than cure: Keep your node updated, don't expose unnecessary ports, and check your dashboard regularly. Most security incidents are preventable with basic hygiene.

📌 Security Checklist

  • ☐ Port 9525 open for P2P (required)
  • ☐ Dashboard (9526) bound to localhost only
  • ☐ Node is running the latest version
  • ☐ Auto-update notifications enabled
  • ☐ Regular backups of data/ folder
  • ☐ Dashboard checked weekly for warnings
  • ☐ System time synchronized (NTP enabled)
