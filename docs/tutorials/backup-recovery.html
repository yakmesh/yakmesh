Backup & Recovery

Protect your node identity and data - restore on any machine

Essential ⏱️ 10 min read 🔐 Security

Why Backup Matters

Your YAKMESH node has a unique identity - a set of cryptographic keys that prove you are you on the mesh network. If you lose these keys, you lose:

  • Your Node ID - You'll get a new random identity
  • Your Karma Score - All your accumulated reputation
  • Your Connections - Trusted peer relationships
  • Your Content Access - Encrypted content you've received

This tutorial shows you how to backup everything important and restore it on a new machine. It takes about 10 minutes and could save you from starting over from scratch.

📋 What to Backup

There are two main things you need to backup: your identity (keys) and your data (stored content).

Critical Files (Must Backup)

📁 keys/ ← Your cryptographic identity
🔑 node.key ← Private key (NEVER share this)
🔑 node.pub ← Public key
🔑 signing.key ← Message signing key
📄 identity.json ← Your Node ID and metadata

Important Files (Recommended)

📁 data/ ← Your stored content
📁 shares/ ← Files you're sharing
📁 received/ ← Downloaded content
📁 blocks/ ← Content chunks

Optional Files

📄 config.yaml ← Custom settings (can be recreated)
📁 cache/ ← Temporary files (auto-regenerated)
📁 logs/ ← Log files (usually not needed)

🚨 Security Warning: Your keys/ folder contains your private keys. Treat backups of this folder like passwords - encrypt them and store them securely. Anyone with your keys can impersonate your node.

1 Find Your YAKMESH Data Folder

First, you need to locate where YAKMESH stores its data. The location depends on your operating system:

Windows

# Default location
%APPDATA%\yakmesh\

# Full path example
C:\Users\YourName\AppData\Roaming\yakmesh\

macOS

# Default location
~/Library/Application Support/yakmesh/

# Or check with
ls -la ~/Library/Application\ Support/yakmesh/

Linux

# Default location
~/.config/yakmesh/

# Or following XDG spec
$XDG_CONFIG_HOME/yakmesh/

Using the CLI

# Let YAKMESH tell you where it stores data
yakmesh config get data_dir

# Output example:
# data_dir: /home/user/.config/yakmesh/

💡 Tip: If you used a custom installation path, check your config.yaml file or run yakmesh config get to see all paths.

2 Export Your Node Identity

YAKMESH provides a convenient command to export your identity in a portable, encrypted format:

Quick Export (Encrypted)

# Export to an encrypted file
yakmesh identity export --output my-backup.yak

# You'll be prompted for a password:
# 🔐 Enter backup password: ********
# 🔐 Confirm password: ********
# ✅ Identity exported to: my-backup.yak

This creates a single encrypted file containing your keys and identity. Remember the password - you'll need it to restore!

Export with Custom Options

# Include additional metadata
yakmesh identity export --output backup.yak --include-config

# Use stronger encryption (slower but more secure)
yakmesh identity export --output backup.yak --encryption-strength high

# Export without password (not recommended)
yakmesh identity export --output backup.yak --no-encrypt

⚠️ Important: Store your backup password somewhere safe! If you forget it, the backup file is useless - encrypted data cannot be recovered without the password.

View Export Contents (Without Secrets)

# See what's in an export file
yakmesh identity inspect my-backup.yak

# Output:
# 📦 Backup Contents:
#    Node ID:     doko-node-qubit-lattice-pq-a7x9
#    Created:     2025-01-15 14:32:00
#    Includes:    keys, identity, peers
#    Encrypted:   Yes (AES-256-GCM)
#    Size:        2.4 KB

3 Backup Your Data Folder

If you want to backup your stored content (shared files, received files), you'll need to copy the entire data folder. This can be large depending on how much content you have.

Using YAKMESH Export (Recommended)

# Export everything including content
yakmesh backup create --output full-backup.tar.gz

# This creates a compressed archive with:
# - Your identity (encrypted)
# - Your configuration
# - Your shared content
# - Your received content

Manual Backup (Alternative)

Windows (PowerShell):

# Stop YAKMESH first
yakmesh stop

# Copy the entire folder
Copy-Item -Recurse "$env:APPDATA\yakmesh" "D:\Backups\yakmesh-backup"

# Or create a zip file
Compress-Archive -Path "$env:APPDATA\yakmesh" -DestinationPath "D:\Backups\yakmesh-backup.zip"

macOS / Linux:

# Stop YAKMESH first
yakmesh stop

# Create a tarball
tar -czvf ~/yakmesh-backup.tar.gz ~/.config/yakmesh/

# Or for macOS
tar -czvf ~/yakmesh-backup.tar.gz ~/Library/Application\ Support/yakmesh/

💡 Tip: Always stop YAKMESH before backing up manually to avoid copying files that are being written to. The yakmesh backup create command handles this automatically.

4 Selective Backup (Keys Only)

If you only care about preserving your identity (Node ID and karma), you can backup just the keys folder. This creates a much smaller backup. 

# Export just identity (smallest backup)
yakmesh identity export --output identity-only.yak

# File size: ~2-5 KB
# Contains: keys, node ID, basic config

Compare this to a full backup:

Identity Only (~5 KB)

  • ✅ Your Node ID
  • ✅ Your Karma Score
  • ✅ Encryption keys
  • ❌ Shared files
  • ❌ Downloaded content

Full Backup (varies)

  • ✅ Your Node ID
  • ✅ Your Karma Score
  • ✅ Encryption keys
  • ✅ Shared files
  • ✅ Downloaded content

ℹ️ Recommendation: At minimum, always keep an identity backup. Do full backups periodically if you have important content stored locally.

5 Restore from Backup

Now let's restore your backup on a new machine. First, install YAKMESH on the new computer, then restore your identity before starting the node.

Step A: Install YAKMESH

# Install YAKMESH (don't start it yet!)
# Use your preferred installation method from the Getting Started guide

# Verify installation
yakmesh --version

Step B: Restore Identity

# Restore from encrypted export
yakmesh identity import my-backup.yak

# Enter your backup password when prompted:
# 🔐 Enter backup password: ********
# 
# ✅ Identity restored successfully!
#    Node ID: doko-node-qubit-lattice-pq-a7x9
#    Keys:    3 files restored
#    Config:  Default settings applied

Step C: Restore Full Backup (Optional)

# If you have a full backup with content
yakmesh backup restore full-backup.tar.gz

# This restores:
# - Identity and keys
# - Configuration
# - Shared content
# - Downloaded files

Step D: Start Your Node

# Start YAKMESH with your restored identity
yakmesh start

# Verify it's using your old Node ID
yakmesh status

# 🏔️ YAKMESH Node Status
# Node ID: doko-node-qubit-lattice-pq-a7x9 ← Same as before!
# Status:  🟢 Online

💡 Tip: After restoring, your node will reconnect to old peers automatically. Your karma score syncs from the mesh network within a few minutes.

6 Manual Restore (If Needed)

If you have a manual backup (copied folder or tarball), here's how to restore it:

Windows

# Make sure YAKMESH is not running
yakmesh stop

# If the folder exists, back it up first
Move-Item "$env:APPDATA\yakmesh" "$env:APPDATA\yakmesh-old"

# Extract or copy your backup
Expand-Archive "D:\Backups\yakmesh-backup.zip" -DestinationPath "$env:APPDATA"

# Or if you copied a folder
Copy-Item -Recurse "D:\Backups\yakmesh-backup" "$env:APPDATA\yakmesh"

macOS / Linux

# Make sure YAKMESH is not running
yakmesh stop

# Back up existing data (if any)
mv ~/.config/yakmesh ~/.config/yakmesh-old

# Extract tarball
tar -xzvf ~/yakmesh-backup.tar.gz -C ~/

# Start YAKMESH
yakmesh start

Restore Keys Only (Minimal)

# If you only have the keys folder backed up
mkdir -p ~/.config/yakmesh
cp -r /path/to/backup/keys ~/.config/yakmesh/

# Let YAKMESH recreate other files
yakmesh start

📁 Important Files Explained

Here's a deeper look at what each important file does:

🔑 keys/node.key

Your private key. This is the most important file - it proves your identity on the network. It's used to sign messages and decrypt content sent to you. NEVER share this file.

🔑 keys/signing.key

Used for cryptographic signatures on messages you send. This is derived from your main key but kept separate for security reasons.

📄 keys/identity.json

Contains your public Node ID, creation date, and protocol version. This information is public - it's what other nodes see when they connect to you.

📁 data/shares/

Index of files you're currently sharing. The actual files stay in their original locations; this folder contains metadata and content hashes.

📁 data/blocks/

Content-addressed storage chunks. Files are split into blocks and stored here by their hash. Can be regenerated from shares/received if lost.

✅ Backup Best Practices

1.

Use Strong Backup Passwords

Use a unique, strong password for your identity export. Consider using a password manager.

2.

Store Backups in Multiple Locations

Keep copies on an external drive, cloud storage (encrypted), and/or a USB drive in a safe place.

3.

Backup Regularly

Identity backups only need to be done once (keys don't change), but data backups should be done regularly if you're storing important content.

4.

Test Your Backups

Periodically verify your backups work by using yakmesh identity inspect to check the backup file is readable.

5.

Never Share Key Files

Your private keys should never be shared, emailed, or uploaded unencrypted. The encrypted export file is safe to store anywhere.

🔧 Troubleshooting

"Wrong password" error

Make sure you're using the exact password from when you created the backup. Passwords are case-sensitive. If you've forgotten it, the backup cannot be recovered.

"Corrupted backup file" error

The backup file may have been damaged during transfer. Check if you have another copy. For manual backups, try extracting individual files instead of the whole archive.

Node ID changed after restore

This means the restore didn't work correctly. Stop YAKMESH, delete the new identity, and try the restore again. Make sure you're restoring before first starting the node.

Karma score is zero after restore

Your karma score is synchronized from the network, not stored in your backup. Give it a few minutes after starting your node - it will sync automatically from peer attestations.

"Permission denied" on Linux/macOS

# Fix permissions on restored files
chmod 700 ~/.config/yakmesh/keys/
chmod 600 ~/.config/yakmesh/keys/*
