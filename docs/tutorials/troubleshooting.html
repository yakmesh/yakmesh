Solutions to common YAKMESH problems

Having issues? Find quick solutions to the most common problems here.

Node Won't Start

Error: EADDRINUSE - Port already in use

→ Another process is using the port (usually 3000 or 8080)

This happens when you try to start a second instance or a previous instance didn't shut down properly.

Find and kill the process:

# Windows - Find process on port 3000
netstat -ano | findstr :3000
# Kill the process (replace 12345 with actual PID)
taskkill /PID 12345 /F

# macOS/Linux - Find and kill in one command
lsof -ti:3000 | xargs kill -9

# Or just use a different port:
yakmesh start --port 3001

Error: Cannot find module '...'

→ Dependencies are missing or corrupted

This usually happens after an incomplete update or a corrupted node_modules folder.

Reinstall dependencies:

# Remove existing node_modules and reinstall
rm -rf node_modules
npm install

# If that doesn't work, clear npm cache too
npm cache clean --force
rm -rf node_modules package-lock.json
npm install

Error: Permission denied (EACCES)

→ File permission issues or need elevated privileges

Windows:

# Run terminal as Administrator
# Right-click Terminal → Run as Administrator
yakmesh start

macOS/Linux:

# Fix ownership of the directory
sudo chown -R $USER:$USER ~/.yakmesh

# If binding to port below 1024 (not recommended)
sudo yakmesh start --port 443

⚠️ Avoid running as root unless absolutely necessary. Instead, use ports above 1024 or fix file permissions.

Can't Connect to Peers

0 peers connected / "No peers available"

→ Check your network and firewall settings

1. Check firewall settings:

# Windows - Allow through firewall
netsh advfirewall firewall add rule name="YAKMESH" dir=in action=allow protocol=TCP localport=8080
netsh advfirewall firewall add rule name="YAKMESH UDP" dir=in action=allow protocol=UDP localport=8080

# Linux (ufw)
sudo ufw allow 8080/tcp
sudo ufw allow 8080/udp

# macOS - Allow in System Preferences → Security → Firewall → Options

Can connect locally but not to internet peers

→ NAT/Router issues - ports may not be forwarded

If you're behind a router, you may need to set up port forwarding or use UPnP.

Options:

  • Enable UPnP in your router settings (automatic port forwarding)
  • Manual port forward: Forward TCP/UDP 8080 to your computer's local IP
  • Use NAT traversal: yakmesh start --enable-nat-traversal

💡 Quick test: Visit canyouseeme.org and check if port 8080 is open.

Bootstrap servers unreachable

→ Network issue or bootstrap servers temporarily down

Test connectivity:

# Test if you can reach bootstrap servers
ping bootstrap.yakmesh.network

# If that fails, check your internet
ping 8.8.8.8

# Try alternative bootstrap servers
yakmesh start --bootstrap "bootstrap2.yakmesh.network:8080"

If bootstrap servers are down, you can still connect by manually adding known peer addresses.

Dashboard Not Loading

Browser shows "Connection refused" or blank page

→ Server might not be running or wrong address

Check if server is running:

# Check if yakmesh process is running
# Windows
tasklist | findstr yakmesh

# macOS/Linux
ps aux | grep yakmesh

# Check what's listening on port 3000
# Windows
netstat -an | findstr 3000

# macOS/Linux
lsof -i :3000

Works with 127.0.0.1 but not localhost (or vice versa)

→ DNS or hosts file issue

Some systems have localhost mapped differently. Try both:

  • http://localhost:3000/dashboard
  • http://127.0.0.1:3000/dashboard

Dashboard looks broken / old version

→ Browser cache issue

Clear cache:

  • Hard refresh: Ctrl+Shift+R (Windows/Linux) or Cmd+Shift+R (macOS)
  • Clear site data: Open DevTools (F12) → Application → Clear Storage
  • Incognito mode: Try accessing in a private/incognito window

Can't access from another device on same network

→ Firewall blocking or wrong binding address

# Start with binding to all interfaces
yakmesh start --host 0.0.0.0 --port 3000

# Then access from other device using your computer's IP:
# http://192.168.1.100:3000/dashboard

yak:// Links Not Working

Browser doesn't recognize yak:// protocol

→ Protocol handler not registered

Register the protocol:

# Run the registration command
yakmesh register-protocol

# Windows: This adds a registry entry
# macOS: This updates Info.plist handlers
# Linux: This creates a .desktop file in ~/.local/share/applications

You may need to restart your browser after registration.

yak:// links open but content doesn't load

→ Node not running or content not available

Checklist:

  • Is your node running? Check the dashboard at localhost:3000
  • Are you connected to peers? You need peers to find content
  • Is the content still available? Content may have expired or been removed
  • Check content hash: Verify the hash in the URL is correct

"Content not found on mesh"

→ No peers have the content cached

Content on the mesh is distributed - if no one has it cached, it won't be available.

ℹ️ How YAKMESH content works: Content is stored across the network. If the original uploader and all seeders go offline, content becomes unavailable until someone with a copy comes back online.

Slow Performance

Downloads are very slow

→ Check peer count - need enough good peers

Check peer status:

# View connected peers
yakmesh peers list

# Check peer quality scores
yakmesh peers stats

# Optimal range: 10-50 peers
# Too few = slow downloads
# Too many = connection overhead

High CPU usage

→ Too many operations or verification backlog

Reduce load:

# Limit concurrent operations
yakmesh config set max-concurrent-downloads 3
yakmesh config set max-concurrent-uploads 3

# Reduce verification intensity
yakmesh config set verification-threads 2

# Check what's consuming resources
yakmesh status --verbose

Running out of disk space

→ Cache and stored content building up

Clean up storage:

# Check storage usage
yakmesh storage stats

# Clear cache (won't delete your files)
yakmesh cache clear

# Set cache size limit
yakmesh config set cache-size-limit 5GB

# Clean old content
yakmesh storage prune --older-than 30d

Network congestion / bandwidth issues

→ Set upload/download limits

# Limit bandwidth usage
yakmesh config set max-upload-rate 10MB
yakmesh config set max-download-rate 50MB

# Schedule heavy operations for off-peak hours
yakmesh config set quiet-hours "02:00-06:00"

Time Sync Issues

Warning: Clock drift detected / MANI time sync failed

→ System clock is out of sync with network time

YAKMESH uses the MANI time synchronization system which is critical for content verification and consensus.

Sync your system clock:

# Windows - Sync with internet time
w32tm /resync /force

# macOS - Enable automatic time
sudo sntp -sS time.apple.com

# Linux - Use systemd-timesyncd or chrony
sudo timedatectl set-ntp true
sudo systemctl restart systemd-timesyncd

MANI can't reach time sources

→ Firewall blocking NTP or mesh time servers

Allow NTP traffic:

# Windows
netsh advfirewall firewall add rule name="NTP" dir=out action=allow protocol=UDP remoteport=123

# Linux
sudo ufw allow out 123/udp

# Test NTP connectivity
ntpdate -q pool.ntp.org

💡 Tip: MANI uses multiple time sources including NTP servers and mesh peer consensus. If external NTP is blocked, it can still sync from trusted peers.

Conflicts with other NTP software

→ Multiple time sync services running

If you have other NTP clients (like chrony, ntpd), they may conflict with MANI.

# Check what's managing time
timedatectl status

# Disable conflicting service (example)
sudo systemctl stop ntpd
sudo systemctl disable ntpd

# Let MANI handle time sync
yakmesh config set mani-time-sync enabled

Getting Help

Enable Debug Mode

Debug mode provides detailed logging to help diagnose issues:

# Start with debug output
yakmesh start --debug

# Or enable debug for specific module
yakmesh start --debug=network
yakmesh start --debug=storage
yakmesh start --debug=mani

# Save debug output to file
yakmesh start --debug > yakmesh-debug.log 2>&1

Log File Locations

Windows: %APPDATA%\yakmesh\logs\
macOS: ~/Library/Logs/yakmesh/
Linux: ~/.yakmesh/logs/
# Open logs folder
yakmesh logs --open

# View recent logs
yakmesh logs --tail 100

# Search logs for errors
yakmesh logs --grep "ERROR"

Report Issues on GitHub

Found a bug or have a feature request? Open an issue on GitHub:

Open GitHub Issues

ℹ️ When reporting issues, include:

  • YAKMESH version (yakmesh --version)
  • Operating system and version
  • Steps to reproduce the problem
  • Relevant log output (sanitize any private data)

🤔 Still Stuck?

If none of these solutions worked, try these steps in order:

  1. Restart your node - Sometimes a fresh start fixes things
  2. Update to latest version - npm update -g yakmesh
  3. Check GitHub issues - Someone may have already solved your problem
  4. Ask in Discord - The community is usually quick to help
  5. Fresh install - As a last resort, backup keys and reinstall
