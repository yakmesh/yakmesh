Using with a Domain Name

15 min

Point example.com to your YAKMESH node

Make your node accessible via a custom domain with HTTPS. Professional setup for production deployments.

📋 What You'll Learn

  • • Configure DNS records (A, CNAME) for your domain
  • • Set up free HTTPS with Let's Encrypt
  • • Optional: Use Cloudflare for CDN and DDoS protection
  • • Optional: Configure nginx as a reverse proxy
  • • Update YAKMESH config for custom domain

⚡ Prerequisites

  • • A running YAKMESH node (see Getting Started)
  • • A domain name you control (e.g., from Namecheap, GoDaddy, Cloudflare)
  • • A public IP address (port forwarding configured on your router)
  • • Basic terminal access to your server
1

Get Your Public IP Address

First, find your server's public IP address. This is what your domain will point to. 

# On Linux/Mac
curl ifconfig.me

# On Windows PowerShell
(Invoke-WebRequest -Uri "https://api.ipify.org").Content

You should get an IP address like 203.0.113.45.

💡 Dynamic IP?

If your ISP assigns a dynamic IP, consider using a dynamic DNS service like DuckDNS or No-IP.

2

Configure DNS Records

Log in to your domain registrar's DNS management panel and add these records:

Option A: Root Domain (example.com)

Type Name Value TTL
A @ 203.0.113.45 3600

Option B: Subdomain (mesh.example.com)

Type Name Value TTL
A mesh 203.0.113.45 3600
CNAME www.mesh mesh.example.com 3600

DNS changes can take up to 48 hours to propagate, but usually complete within 15-30 minutes. 

# Verify DNS propagation
nslookup mesh.example.com
# Or use dig
dig mesh.example.com +short
3

Configure Port Forwarding

If your YAKMESH node is behind a router, forward these ports to your server:

Port Protocol Purpose
80 TCP HTTP (for Let's Encrypt verification)
443 TCP HTTPS (secure traffic)
3000 TCP YAKMESH Dashboard (if exposed directly)
9001 TCP WebSocket peer connections

🔒 Security Note

Only forward the ports you actually need. If using nginx as a reverse proxy, you only need 80 and 443.

4

Set Up HTTPS with Let's Encrypt

Let's Encrypt provides free SSL certificates. We'll use Certbot to automate the process.

Install Certbot

# Ubuntu/Debian
sudo apt update
sudo apt install certbot

# CentOS/RHEL
sudo yum install certbot

# macOS with Homebrew
brew install certbot

Obtain Certificate (Standalone Mode)

Stop any service using port 80, then run: 

# Stop YAKMESH temporarily
npx yakmesh stop

# Get certificate
sudo certbot certonly --standalone -d mesh.example.com

# Certificate files will be saved to:
# /etc/letsencrypt/live/mesh.example.com/fullchain.pem
# /etc/letsencrypt/live/mesh.example.com/privkey.pem

Auto-Renewal

Set up automatic certificate renewal: 

# Test renewal
sudo certbot renew --dry-run

# Certbot automatically adds a cron job for renewal
5

Configure YAKMESH for HTTPS

Update your yakmesh.config.js to use SSL: 

// yakmesh.config.js
export default {
  node: {
    name: 'my-mesh-node',
    publicUrl: 'https://mesh.example.com',
  },
  
  server: {
    port: 443,
    ssl: {
      enabled: true,
      cert: '/etc/letsencrypt/live/mesh.example.com/fullchain.pem',
      key: '/etc/letsencrypt/live/mesh.example.com/privkey.pem',
    },
  },
  
  websocket: {
    port: 9001,
    ssl: {
      enabled: true,
      cert: '/etc/letsencrypt/live/mesh.example.com/fullchain.pem',
      key: '/etc/letsencrypt/live/mesh.example.com/privkey.pem',
    },
  },
};

Restart YAKMESH to apply changes: 

npx yakmesh start
6

Cloudflare Integration (Optional)

Cloudflare provides free CDN, DDoS protection, and simplified SSL. Here's how to set it up:

Add Your Domain to Cloudflare

  1. Create a free account at cloudflare.com
  2. Add your domain and scan existing DNS records
  3. Update your domain's nameservers to Cloudflare's (provided during setup)
  4. Wait for nameserver propagation (up to 24 hours)

Configure Proxy Settings

Record Proxy Status Notes
A (mesh) 🟠 Proxied Dashboard traffic goes through Cloudflare
A (ws.mesh) ⚪ DNS Only WebSocket traffic bypasses proxy

SSL/TLS Settings

In Cloudflare dashboard → SSL/TLS:

  • • Set encryption mode to Full (strict) if you have Let's Encrypt
  • • Or use Full with Cloudflare Origin Certificates
  • • Enable Always Use HTTPS

⚠️ WebSocket Consideration

Cloudflare's free tier supports WebSockets, but for best performance with YAKMESH peer connections, use a separate subdomain (e.g., ws.mesh.example.com) with proxy disabled.

7

Nginx Reverse Proxy (Optional)

If you're running multiple services, nginx can route traffic to YAKMESH:

Install nginx

# Ubuntu/Debian
sudo apt install nginx

# Start nginx
sudo systemctl start nginx
sudo systemctl enable nginx

Configure Virtual Host

Create /etc/nginx/sites-available/yakmesh: 

server {
    listen 80;
    server_name mesh.example.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name mesh.example.com;

    ssl_certificate /etc/letsencrypt/live/mesh.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/mesh.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256;
    ssl_prefer_server_ciphers off;

    # Security headers
    add_header X-Frame-Options DENY;
    add_header X-Content-Type-Options nosniff;
    add_header X-XSS-Protection "1; mode=block";

    # Dashboard and API
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # WebSocket connections
    location /ws {
        proxy_pass http://127.0.0.1:9001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 86400;
    }
}

Enable and Test

# Enable the site
sudo ln -s /etc/nginx/sites-available/yakmesh /etc/nginx/sites-enabled/

# Test configuration
sudo nginx -t

# Reload nginx
sudo systemctl reload nginx
8

Update Config for Reverse Proxy

When using nginx, YAKMESH runs on localhost without SSL (nginx handles it): 

// yakmesh.config.js - behind reverse proxy
export default {
  node: {
    name: 'my-mesh-node',
    publicUrl: 'https://mesh.example.com',
  },
  
  server: {
    host: '127.0.0.1',  // Only accept local connections
    port: 3000,
    ssl: { enabled: false },  // nginx handles SSL
    trustProxy: true,  // Trust X-Forwarded headers
  },
  
  websocket: {
    host: '127.0.0.1',
    port: 9001,
    publicUrl: 'wss://mesh.example.com/ws',
  },
};

✅ Verify Your Setup

Test that everything works: 

# Check HTTPS is working
curl -I https://mesh.example.com

# Check health endpoint
curl https://mesh.example.com/health

# Test WebSocket (requires wscat: npm install -g wscat)
wscat -c wss://mesh.example.com/ws

You should see your node responding with valid SSL certificates and health status.

🔧 Troubleshooting

DNS not resolving?

Wait longer for propagation, or try nslookup from different networks.

Certificate errors?

Ensure certificates are readable by YAKMESH/nginx. Check permissions with ls -la /etc/letsencrypt/live/.

Connection refused?

Check firewall rules with sudo ufw status and port forwarding on your router.

WebSocket failing?

Ensure nginx config has proper WebSocket upgrade headers. Check logs with sudo tail -f /var/log/nginx/error.log.

🎉 You Did It!

Your YAKMESH node is now accessible via your custom domain with secure HTTPS. Share your public URL https://mesh.example.com with peers so they can connect to your node.
